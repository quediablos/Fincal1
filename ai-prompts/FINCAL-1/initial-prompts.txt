


Write a full stack application/system that consists of one backend written in go, and the front end that consumes the endpoints of the backend.

1.Backend: written in go.
1.1.Endpoints:
1.1.1. Addition endpoint which adds two numbers and returns its response.
       Validations: both inputs are validated against being non-empty and numeric.
	   Refer to "error response" if validations fail.
	   Refer to "success response" for success case.
	   Request json: {
		"addend1":232.2
		"addend2":-232.1
	   }
	   
1.1.2. Subtraction endpoint which subtracts two numbers and returns its response.
       Validations: both inputs are validated against being non-empty and numeric.
	   Refer to "error response" if validations fail.	 
	   Refer to "success response" for success case.
	   Request json: {
		"minuend":1.2
		"subtrahend":2.1
	   }

1.1.3. Multiplication endpoint which multiplies two numbers and returns its response.
       Validations: both inputs are validated against being non-empty and numeric.
	   Refer to "error response" if validations fail.	
	   Refer to "success response" for success case.
	   Request json: {
		"multiplicand":1.2
		"multiplier":2.1
	   }

1.1.4. Division endpoint which divides two numbers and returns its response.
       Validations: both inputs are validated against being non-empty and numeric. Also the division by zero is checked.
	   Refer to "error response" if validations fail.	
	   Refer to "success response" for success case.	
	   Request json: {
		"dividend":1.2
		"divisor":2.1
	   }

1.2. Response structure
1.2.1. success response: {
	"result":"23.2"
} 

1.2.2. error response: {
	"errors": [
		{
			"errorCode": one of the following: "MISSING_FIELD", "DIVISION_BY_ZERO", "INTERNAL_ERROR"
			"errorClass": one of the following:"VALIDATION", "INTERNAL"
			"errorMessage": depends on the case.
		}
	]
}

1.3.Unit tests: Cover all the code written by unit tests.
1.4. Coverage report: Generate a coverage report for unit tests.

2. Front end: written by react, with typescript, compatible with mobile devices.

2.2. User interface: A user friendly interface that consist of a dial for a calculator.
2.2. APIs consumed: For each operation triggered by its own button, the corresponding endpoint (see section 1.1) of the backend application should be consumed.
2.3. Validations: A seperate layer of validations on UI level should apply for each endpoint just like mentioned in section 1.1 (endpoints). Validations should apply on the fly
as the user types the values without waiting for pressing the operation buttons.
2.4.Unit tests: Cover all the code written by unit tests.
2.5. Coverage report: Generate a converage report for unit tests.

3. Docker Container: Generate a Dockerfile for starting both backend and frontend applications and write the instructions in a README.md file.
